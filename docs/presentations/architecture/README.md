# Architecture timeline deck

**`index.html`** is the architecture timeline deck: 2026-09-22 → 2026-11-17, self-contained,
keyboard navigation, print-to-PDF styling. Sibling of `../design/` (the GUI/UX timeline) —
same visual system, same rules.

Every image is under `assets/`. How each was made:

- **Stage diagrams** (`era*.svg`, `kids-ladder.svg`, `media-proxy.svg`, `backup-flow.svg`):
  hand-drawn SVG, dark ground matching the deck. Each diagram is a simplification of the
  git record; the caption on the slide names the exact commits it compresses. Text is
  set in Arial/Helvetica with plain phrasing — no diagram was generated by an image
  model, and none of them is a measurement, only a shape.

- **Review deep-dive diagrams** (`review-flow.svg`, `request-interface.svg`,
  `key-collision.svg`, `library-source-seam.svg`, `precedence-chain.svg`,
  `route-split.svg`, `personal-data-list.svg`, `srv-clobber.svg`, `coalescer.svg`,
  `wake-budget.svg`, `ssrf-guard.svg`): same constraints. These carry the three
  fresh-context architecture reviews — 2026-11-11 (spec 37), 2026-11-15 (spec 41) and
  2026-11-16 (spec 42) — including the live bugs each one found and the exact
  before/after shape of the fix. The 2026-11-16 security remediation phases
  (docs/security-remediation-plan-2026-11-16.md) are drawn as the SSRF flow.

- **`current-architecture.svg`**: the repository's own `docs/diagrams/architecture.svg`
  (added in `5d67e0f`), reproduced unchanged. Regenerate decisions with
  `decisions/` and `scripts/generate-api-diagram.cjs` (for the API reference); this file
  is a copy — if the repo diagram changes, refresh the copy.

- **No screenshots.** There is nothing to screenshot of a server; the diagrams stand
  in. Device photos and UI captures from the era live in `../design/assets/` and
  `specs/evidence/`.

Coverage notes:

- The passkey/biometrics stage (Oct 24–27) has no dedicated diagram: the mechanism is
  a device enrollment flow best explained by `specs/28-accounts-passkeys-biometrics.md`;
  the slide summarises it in prose.
- The spec 37 diagram compresses ~60 commits into one before/after picture; the spec's
  step table is the authority for what each step did.
- Security chronology (slide 21) lists the commits that closed each door; where an
  audit produced the finding and the fix on the same day, the audit plan commit is
  shown alongside (e.g. `b28bdbf` before the fixes).
- If code and this deck ever disagree, the code wins — file the fix against this folder,
  and update the caption or the diagram in the same change.
