Audiobook Manager - speaker notes

One cue card per slide. Open with the quoted line; the rest is beats, not a script. The talk is allowed to be loose. Total: 5 minutes + Q&A. Deck: index.html · Edit mode: press E in the deck.

1 · TITLE - 10s

“This is Audiobook Manager.”

  • One sentence: what it is (household library that runs itself), one breath.
  • Do not explain the stack yet.

2 · WHY - 40s

“Audiobooks are a mess - four apps and a folder of MP3s.”

  • The scene: Audible + Google Play Books + Libri.fm, plus library loans, plus mystery VLC files.
  • Nobody could say where any book lived. Copying meant cables and chore work.
  • The insight: one server at home, files in, a shared library out - play anywhere, pick up where you left off, downloads when you’re away.
  • Who it’s for: audiobook lovers. It runs on a home PC - an always-on Pi or a temporary laptop.

“Day one I built a grid of broken covers. Day two it stopped being a toy.”

  • Day 1 (Sep 22): scaffold - is browse → pick → press play worth building? Answered that afternoon with placeholders.
  • Day 2 (Sep 23): the scanner read real folders; chapter playback arrived the same day.

  • Nov 11 → 13 - a fresh-context review found one rule copied in three places; ~60 commits consolidated it into single, tested modules - route table split, one client request interface, one offline key format. Merged f024c6b (spec 37).

11 · CHALLENGE 1 - ~25s · free tools, finite tokens, ensuring consistency across agents and sessions

"The commits themselves became the handoff."

  • Our group presentation covered the handoff.md approach - this project used it too, then found better: the commit log as the handoff, with comprehensive multi-phase plans and step-by-step checkboxes, committed per block of work with agent-written messages.
  • Why it worked: debugging got easier, documentation stayed reliable, any agent could resume from any commit.
  • GitHub CI caught what local missed: a client type error Vitest never typechecks (CI's typecheck gate caught it), a CSS budget overrun nobody noticed locally.
  • Numbers: 467 commits and counting · 45 specs · 39 ADRs · 1,983 tests.

12 · CHALLENGE 2 - ~25s · hallucinations

"Hallucinations - the three agent mistakes I can point at."

  • Double-encoded bodies - symptom: every save claimed to work, nothing reached the server. Cause: JSON inside JSON at three call sites. Fix: body typed object; the typecheck gate now refuses the whole class.
  • Unreachable onEnded - symptom: chapter advance green in tests, dead in one-file books. Cause: the branch could never run; tests had fabricated an impossible event order. Fix: deleted it; player rebuilt (ADR 017).
  • Christmas Carol, recommended as miscellany - symptom: arbitrary Discover suggestions, seeded by the catch-all "misc" genre. Cause: weight-1.0 seed into subject:misc, plus a provider refactor that pooled incompatible fields. Fix: catch-all excluded, deterministic tie-break, tests (31a03a8); pooling reworked, ADR 039 (39ab7e7, 605d391, 23b1ae9).
  • Shape to remember: symptom, cause, fix - every story, every time.

13 · CHALLENGE 3 - ~25s · the offline split

"A copy on the phone, not a second server."

  • Per-server replica, downloads for the plane, background audio, reconnect push.
  • The tension: phones are a version behind, mid-chapter, on a flaky link - sync is a push on reconnect, never a guess mid-play.
  • Kids get the same visibility predicate everywhere - server-side, fail-closed, including offline.

Q&A - likely questions, crisp answers

  • Why a server at all? One library per house, devices come and go, files are read-only - sync is reconciliation by theft of the smallest surface: resume position. The phone is the copy; the server is the truth.
  • Why not just Audible? Audible has the library and one ecosystem; this reads anything - library loans, friends’ rips, public-domain LibriVox - one place, one progress bar.
  • What did the agents actually do? Everything from the first scaffold to the last audit - I directed, reviewed, tested and merged; I didn’t write the code by hand. The discipline was the specs, the tests and the reviews.
  • Did anything ship untested? Honestly: yes - until Nov 16-17. The security remediation day and specs 45 were about exactly that. Suites are 975/1008 now; “done” means green twice, in CI, and verified on hardware where it touches the phone.
  • How does offline sync work? One-directional push on reconnect; ties go to the server; client clocks are never trusted. (Spec 44.)
  • What would you change architecturally? Start with the per-server key format on day one (spec 37 step 2 taught the whole codebase to agree on it). Everything else followed from not having it.
  • Why free models only? Cost was the constraint; the constraint produced the discipline. Rate limits → paperwork → reviews → a codebase that can be audited by a stranger (spec 42). Would I still do it paid? Probably the same, faster.
