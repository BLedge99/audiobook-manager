Whythe origin story

Audiobooks are a mess - four or more apps and a folder of MP3s

Audible, Google Play Books, Libri.fm, and more, plus library loans, files from who-knows-where that only play in VLC. Every book lives somewhere different, and nobody can manage where.

Copying files means cables and chore-work, and big audiobooks clog device storage. So the fix seemed simple: one server at home manages the files, play anywhere, pick up where you left off across multiple devices, download files to your device for offline listening.

Who it’s for: Audiobook lovers. It runs on a home PC, whether that’s an always-on Raspberry Pi, or a temporary laptop hosting.

Four apps deep, one folder of “Mum’s rips” - and no single place with the whole collection

Challenge 1 · free toolshow agents stayed consistent

Free tools, finite tokens,
ensuring consistency across agents and sessions

As I mentioned in our group presentation, we used handoff.md to track progress and tasks, so that every agent understood what to do next. We used it for much of this project too.

But we found a better way. The repo is nearing 500 commits - not because there’s 50GB of code in here, it’s because the commits themselves became the handoff, a far more reliable and valuable record than handoff.md ever could be.

We wrote comprehensive multi-phase plans with step-by-step detail, worked through them one block at a time, and committed after each block with an agent-written message. That made debugging easier, and the history became the documentation.

And GitHub’s CI caught real bugs the local run missed: a client type error Vitest never typechecks (CI’s typecheck gate caught it), a CSS bundle-budget overrun nobody noticed locally.

Challenge 2 · when the agents were wrongsymptom, cause, fix

Hallucinations

StoryWhat went wrongWhy (the code)The fix
Double-encoded bodies The app claimed every save worked. Nothing reached the server. Silent no-ops at three call sites. The old helpers took a string body, so three call sites did JSON.stringify(). The new request() serialised it again: JSON inside JSON, and the server read a string where it expected an object. body is typed object; that version doesn’t compile. The typecheck gate in make test (spec 37 step 0.1) catches the whole class, not just these three.
Unreachable onEnded Chapter auto-advance was green in tests and dead in one-file books. The playhead just sat at the boundary. The onEnded branch could never be reached for single-file books. The tests had fabricated an event order that never occurs, so the suite “proved” nothing. Deleted the branch; no extra guard. The player was rebuilt around one chapter model (ADR 017).
Christmas Carol, recommended as miscellany Discover answered arbitrary results. One book seeded the catch-all genre “misc”, and users were handed a junk drawer of suggestions. The misc genre entered the recommendation seed at weight 1.0, so expand() browsed subject:misc. A later agent-co-authored provider refactor pooled incompatible fields and broke Open Library title search. Catch-all excluded from seeds; deterministic tie-break; regression test (31a03a8). Pooling reworked with tests and ADR 039 (39ab7e7). Genre and misc fallbacks restored (605d391, 23b1ae9).
Verification isn’t paranoia - it’s Tuesday · specs 37 · 41 · 42 · 45 exist because agents don’t get tired, they get confident

Challenge 3 · the Android appa replica, not a second server

Offline without
becoming a second server

The app on the phone is a careful copy of the library, keyed per server; rows and files agree on whose “book #7” it is. It downloads for the plane, plays with the screen off, and pushes progress on reconnect.

No second database to keep in sync, no duplicate enrichment, no drift to babysit - the server is the source of truth; the phone is its replica. If everything were reimplemented client-side, the server would be pointless; the design keeps exactly enough on the device to feel native, nothing more.

Lock-screen controls took real work (media session, WebView); kids accounts get one visibility predicate honoured everywhere, including the offline replica.
